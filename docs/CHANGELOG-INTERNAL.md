### 3. UIモード `nte`（公式サイト風）

- **公式サイトは2つの顔を持つ**（`public_list260427.css` の実測）:
  ニュース一覧＝暗い地／記事本文＝明るい紙。
  → **暗いテーマ＝一覧、明るいテーマ＝記事**に割り当てた。テーマ設定を無視しなくて済む。
- **詳細度の落とし穴**: `html[data-ui='nte']`（0,1,1）では `themes.css` の
  `:root[data-theme='minimal']`（0,2,0）に負けて `--accent` を上書きできない。
  → 変数ブロックだけ **`html:root[data-ui='nte']`（0,2,1）**。
- **公式のシアン `#4fe5fb` は明るい紙で 1.3:1** しかない。
  塗りは実測のまま、**文字に使う側だけ `#0b6f80`（4.8:1）**に落とした。
- **グリッチは公式の keyframes をそのまま移植**。`clip-path: inset()` で切るため
  **文字の複製が要る**。`.page-head h1` を持つページが14種類あり手書きでは足し忘れるので、
  `BaseLayout` 末尾の inline スクリプトで `data-glitch` に機械的に写す
  （`data-astro-rerun` で View Transitions の切替後も走る）。
  公式と変えたのは**回数（infinite → 3回、ホバー中だけ infinite）**と
  **明るいテーマの合成（screen → multiply）**の2点だけ。
- **ポインタ追従**: 公式の `mouseTracking260603.js` に倣い、
  ヒーローの光を `--nte-mx` / `--nte-my` で寄せる。
  JS が動かなければ既定値のまま。`hover: hover` とモーション設定を見て止める。

### 4. エンドフィールドの作り込み

- **下層ページのヘッダー帯**: 実測 `border-bottom: 1rem solid #c6c6c6` ＋
  `linear-gradient(180deg, white 15.5625rem, #fffa00 0, #fffa00)`
  → 上が白・下が蛍光イエローの2段ベタ。
- **黒い正方形に黄色のアイコン**（実測 `.decoHeader .icon`）。
- **一覧の区切りは全幅ではなく中央寄せ90%幅**（実測 `.dropDownItem:before`）。
- **ページャ**: ピル型の外枠＋二重リングの丸ボタン（外が灰 `.375rem`、内が白 `.25rem`）。
  ホバーで `#fffa00`、押下で `#eeea00`。
- **カラーラインは3色**（`#ff00f0 → #fffa00 → #00ffa2`）。2色だと思っていたのは誤り。
- **ハザード帯は −45度・線3px・周期6px・`#1f1f22`**。45度・黄色は誤り。
- **角丸は `.25rem`（4px）が19回で最多**。2px は誤り。
- **導入ブロック**はローディング画面の再現（黒地＋等高線＋左端の黄色い縦バー＋大きな数字）。
  **数字とバーの割合は実データ**（記事が1本以上あるセクション ÷ 全セクション）。
- **一覧の表示形式**（`html[data-ef-view]`）: `rows` / `grid` / `detail`。
  `localStorage['endfield.view']` に残し、**描画前に起動スクリプトが当てる**。
  NTE 側の `data-listview` とは別の仕組み（専用レイアウトで設定パネルを読まないため）。
  **記事0件のときは切り替えを出さない**。
- **縦書きは断念**。`writing-mode: vertical-rl` は縦組みメトリクスを持たないフォントで
  **字が重なる**。`getClientRects()` は正常値を返すので数値では気づけず、
  高解像度で撮って目視して分かった。横組みの短いラベルに替えた。

**構成**

| `src/components/SiteStateGate.astro` | 案内を重ねる枠。6レイアウトすべてに置く |

**静的サイトであることの帰結（ごまかさない）**

- 認証はできない。合言葉は `ADMIN_PASSCODE` を**ビルド時に SHA-256 化**して埋め、
  照合はブラウザの中（Web Crypto）。総当たりは防げない。**画面にそう書いた**。
- 書き込み先が無いので、管理ページの操作は `localStorage` にしか残らない
  （＝その端末だけ）。全員に配るには `NOTICES` / `DEFAULT_SITE_STATE` を書き換える。
  管理ページに**貼り付け用の書き出しボタン**を付けてその橋渡しにした。

**閉じ込めを作らない**

停止（suspended）は閉じられない案内を出すが、`/admin/` `/legal/` `/notices/` では
案内を出さない。ゲートの中からこの3つへリンクしているので、行った先で塞ぐと
「解除もできず規約も読めない」状態になる。

**踏んだ不具合**

`/admin/` を解除済みで開くと画面が真っ白（パネルが出ない）。
初期表示 `show(...)` をスクリプト冒頭で呼んでいたため、`renderState()` が
**まだ代入されていない `var current`** を読んで `TypeError` で停止していた。
関数宣言は巻き上げられるが `var` の代入は巻き上げられない。
→ 初期表示の呼び出しを**スクリプト末尾**へ移した。ビルドも型検査も通る種類の事故なので、
Playwright で「解除 → 別ページ → 戻る」を実際に踏んで見つけた。

## beta v0.12.0 追記 — スマホUIとリファクタリング

### 9. 320px 幅の横スクロールを直した

`.app { grid-template-columns: 1fr }` の `1fr` は最小が `auto`（＝中身の min-content）
なので、ヘッダーの中身が縮まないぶんだけ列が広がり、**NTE 側の全ページ**で

→ **`minmax(0, 1fr)`**。あわせてブランド名を省略できるようにした
（`min-width: 0` は `.brand` と**その中の span の両方**に要る）。
詳しい経緯と調べ方は `docs/FINDINGS.md`。

**権利について伝えたこと**

ゲーム画像の権利は運営元にあり、サイト管理者の許可は権利者の許諾にならないと伝えた。
そのうえで利用者が判断した。**同梱はしない**作りにして、実際に置くかどうかを
利用者の手元の判断に委ねる形にしてある。

#### 6-1. 仕組み — CSS の擬似要素で「重ねる」

絵は `<img>` ではなく **`.avatar::before` の `background-image`** で重ねている。

| なぜ | 説明 |
| --- | --- |
| **失敗しても崩れない** | 画像が読めなければ擬似要素が透明のままで、下の生成アバター（色＋頭文字）が見える。`<img>` の `onerror` を書かなくていい |
| **JS が要らない** | 出どころの切り替えは `html[data-images]` × CSS 変数だけ。View Transitions の影響も受けない |
| **他のUIに漏れない** | ルールがすべて `html[data-ui='base']` の内側にある |

`::after` は既に斜めの光沢に使われていたので `::before` を使った。重なりは下から
**地のグラデ → 絵（z-index 2）→ 光沢 → レア度**。頭文字は z-index 1 なので絵に隠れる。

```css
html[data-ui='base'] .avatar { --av-img: var(--img-local, none); }
html[data-ui='base'][data-images='official'] .avatar {
  --av-img: var(--img-official, var(--img-local, none));  /* 無ければローカルへ落ちる */
}
```

#### 6-2. 置いていない画像の URL を書き出さない

素朴に `/images/characters/<id>.webp` を全カードに書くと、**キャラの数だけ 404 が飛ぶ**。
`src/lib/asset.ts` を新設し、**ビルド時に `fs.existsSync` で有無を確かめて**、
あるものだけ CSS 変数を書き出すようにした（結果は Map にキャッシュ。一覧で数十回呼ばれる）。

`node:fs` を使うのでブラウザへ渡るコードから import できない。
**定数だけの `src/lib/images.ts`（クライアント安全）と、fs を使う `asset.ts` を分けてある。**

#### 6-3. 同梱しない

`public/images/characters/` は `.gitignore` で除外し、**README だけを追跡**している。
置いた端末でしか見えないので、リポジトリにも本番にも画像は入らない。
公式画像は `officialImage`（frontmatter・URL）で**参照するだけ**。

### 7. 管理ページの刷新と、base UI を骨組みから作り替える（2026-09-12・6巡目）

#### 7-1. `/admin/` — 構成を変え、バグを5件直す

**構成**: 上から順に長く積むのをやめ、**タブで4つに分けた**
（サイトの状態 / お知らせ / 表示 / この端末のデータ）。
4つ目は新設で、**いま何が端末に保存されているか**を一覧し、書き出し・消去ができる。
通知は `alert()`（作業が止まる）をやめ、画面下に5秒出る `.admin-toast` にした。

**直したバグ**

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| 削除が**別のお知らせを消しうる** | 表示時の並び順の番号で `splice(i, 1)` していた | **`id` で `filter`** する |
| 同じ日に2件書き出すと**id が衝突** | id が `notice-YYYYMMDD` だけ | **時刻（HHMM）を足す**。id は URL になる |
| 「`maintenance` にしました」と**英語が出る** | 内部の値をそのまま画面へ | ラベル表を `define:vars` で渡して**引く** |
| 合言葉の照合が**無反応**になることがある | `crypto.subtle.digest()` の失敗を拾っていない | `.catch` を足し、文言を出す |
| 同じページで操作が**二重に起きる** | `data-astro-rerun` で再実行されリスナーが重なる | `root.dataset.bound` で1回だけ |

ほかに、日付が空でも今日を補う、`renderImages()` を `show()` から呼ぶ、
クリップボードが使えない環境では `prompt()` に落とす、なども入れた。

#### 7-2. ついでに見つかった既存の不具合（管理ページ以外にも効く）

横あふれを追っていて、**3つとも別の原因**だと分かった。

1. **グリッドの子に `max-width` だけを付けると stretch が切れる**
   → `fit-content` になり、中身の min-content が幅になる（実測 467 > 393）。
   **同じ日に2回踏んだ**（`.admin-page` と base の `.content`）。`width: 100%` を併記する。
2. **閉じた `<details>` の中身は幅を持つ**
   Chromium は `content-visibility: hidden` で隠すので、`display` は `block` のまま
   `getBoundingClientRect()` がサイズを返す。→ `:not([open])` で `display: none`。
3. **`.layout` が `grid-template-columns: 1fr` のままだった**
   `.app` は直していたが、こちらは残っていた。→ `minmax(0, 1fr)`。

さらに、**wiki 切替を開くと右が画面の外に出ていた**（393px の画面で 505px まで）。
閉じているあいだは気づけない種類の不具合。`.wiki-switch` の `position` を外して
**基準をヘッダーに移し**、`left: 12px; right: 12px` で全幅にした。

3つとも `docs/FINDINGS.md` に書いた。

## 2026-09-13 — 公式画像の登録（8巡目）

### 何をしたか

### 直した不具合 — 絵が無いのに枠だけ変わる

`Avatar.astro` は `has-img` を「ローカル画像**か**公式URLがあるとき」に付けていた。
`officialImage` を17件書いた途端、**「置いた画像だけ」を選んでいる端末でも**
`.avatar-block.has-img { aspect-ratio: 3/4 }` が当たり、**絵は出ないのに縦長の枠**になる。

→ `has-img-local` / `has-img-official` に**分けた**。公式側は
`html[data-ui='base'][data-images='official']` の下でだけ効く。

### 一覧の絵の寄せ方（実測して決めた）

750×836 の全身立ち絵を 46px の丸に `cover` で入れると、顔が小さすぎる。
`background-size` と `background-position` を変えて撮り比べた。

| 設定 | 結果 |
| --- | --- |
| `cover` / `center top`（従来） | 全身。顔は豆粒。飾り文字「CHARACTER」が目立つ |
| `300% auto` / `50% 8%` | **寄せすぎ**。頭頂ばかりで顔が枠の下に切れる |
| **`200% auto` / `50% 24%`** | **胸から上。採用**。飾り文字は薄く背景に残る程度 |

飾り文字は顔のすぐ下（画像の縦 36〜42%）にあり、**顔を中心に置くと必ず入る**。
完全に外すには 300% 以上が要るが、そこまで寄せるとキャラによって顔が外れる。

★ この寄せは**公式の画像のときだけ**。置いた画像（`--img-local`）は構図が分からないので触らない。
