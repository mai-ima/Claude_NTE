## ★ Playwright で公式サイトを実際に開く方法（2026-09-07 に確立）

**この環境は Chromium からの外部アクセスを切る**（どのフラグでも `net::ERR_CONNECTION_RESET`）。
一方 **`curl` は通る**。そこで **Playwright の route インターセプトで全リクエストを横取りし、
`curl` で取ってきた中身を返す**。URL は元のままなので、サイトの JS も素直に動く。

```js
await ctx.route('**/*', async (route) => {
  const { body, contentType } = await viaCurl(route.request().url()); // curl を execFile で呼ぶ
  await route.fulfill({ status: 200, body, headers: { 'content-type': contentType } });
});
```

> ⚠ **プロキシのポートはセッションごとに変わる**。`$HTTPS_PROXY` を必ず参照すること
> （前回は古いポートを直書きして全滅し、「ブラウザでは見られない」と誤って結論づけた）。
> ⚠ URL を書き換える方式（ローカル中継サーバー）は **Next.js の内部と衝突して失敗**した
> （`Application error: a client-side exception`）。横取り方式が正解。
> ⚠ 公式サイトはローディングが長い。**45〜75秒**待たないと本編が描画されない。

これで**実画面のスクリーンショットと計算後のスタイル**が取れる。
CSS ファイルの静的解析より遥かに情報量が多い。

## 調べ方（CSS ファイルからの静的解析。上が使えないときの代替）

```bash
# 1. 公式サイトの HTML を取る（curl はプロキシを通る）
curl -s -L --max-time 30 "<公式URL>" -o site.html

# 2. HTML から CSS の URL を拾って全部つなげる
for c in $(grep -oE 'https://[^"]*\.css' site.html | sort -u); do curl -s -L "$c"; echo; done > site.css

# 3. 実際に使われている値を数える（多い順＝主要な値）
grep -oE '#[0-9a-fA-F]{6}|#[0-9a-fA-F]{3}\b|rgba?\([0-9 ,.]+\)' site.css | tr 'A-F' 'a-f' | sort | uniq -c | sort -rn | head -20
grep -oE 'border-radius:[^;}]+' site.css | sort | uniq -c | sort -rn | head
grep -oE 'clip-path:[^;}]+'     site.css | sort | uniq -c | sort -rn | head
grep -oE 'font-family:[^;}]+'   site.css | sort | uniq -c | sort -rn | head
grep -oE 'letter-spacing:[^;}]+' site.css | sort | uniq -c | sort -rn | head
```

> ⚠ **直アクセスでは開けない**が、上の**横取り方式なら開ける**。まずそちらを試すこと。
>
> ⚠ この `grep` の手順は**圧縮された1行 CSS では無言で失敗する**。
> また、HTML から辿れる CSS が本体とは限らない。
> → 下の「★ CSS の静的解析でつまずいた点」に**動く手順**を書いた。そちらを使うこと。

### 形

- `border-radius` は **4px / 2px / .25rem** が中心。**角丸はごく小さい**
  （`50%` は円形ボタン用、`2.625rem` 等はピル型ボタン用）
- **`clip-path: polygon(...)` を多用**。矩形マスクのほか
  `polygon(0 20%,100% 50%,0 80%,0 80%)` のような**斜めの三角**もある
  → 直線と斜めの切り欠きが意匠の一部

### タイポグラフィ

- `Novecentosanswide-Bold / DemiBold / Medium`
  … **幅広・大文字主体のジオメトリックサンセリフ**。英字ラベルに使われている
- `Gilroy-Medium / Light`、独自の `SansMedium / SansRegular / SansBold`
- `letter-spacing` は **-.02em 〜 -.03em（詰める）** が中心。
  一部に `1rem` / `.08em` の大きく開けた指定 → **開けるのはラベル用途**

### 形の作り（2回目の解析で分かったこと）

初回は色と角丸までしか見ていなかった。**作り込みのために掘り直したら、
このゲームらしさの核はここにあった**:

| 見つけたもの | 実測値 | どう効いているか |
| --- | --- | --- |
| **太い罫線** | `border-top: .375rem solid #35373c`（**6px**）ほか上下左右で6回 | 1px の細線ではなく**6px の厚い枠**。これが工業的な重さを出している |
| **45度のハザードストライプ** | `linear-gradient(-45deg, transparent, transparent 13.95%, black 0, black 36.05%, transparent 0, …)` を3種 | 斜めの縞。工事現場の警告帯と同じ意匠 |
| **黄色の発光** | `box-shadow: 0 0 10px #fff000` | 蛍光イエローを**光らせる**（面で塗るだけではない） |
| 下方向のフェード | `linear-gradient(180deg, rgba(0,0,0,0) …)` を14回 | 画像や区画の下端を黒へ溶かす |
| 横方向のマスク | `linear-gradient(90deg, transparent 0, transparent .25rem, black .5rem, black calc(100% - .5rem), …)` | 左右端だけ透かす |
| 斜めの三角 | `clip-path: polygon(0 20%, 100% 50%, 0 80%, 0 80%)` | 矢印・インジケータの形 |
| 大文字化 | `text-transform: uppercase` × 12 | 英字ラベルは**大文字**が基本 |
| 太さ | `font-weight: 400`（12）/ `500`（5）/ `700`（3） | 本文は 400〜500。**700 は要所だけ** |
| 動き | `transition: background-color .2s ease` / `transform .3s` / `color .3s` | **0.2〜0.3秒**。速すぎず遅すぎず |
| スクロールバー | `::-webkit-scrollbar { display: none }` | **隠す** |

**計算後のスタイル（実測）**: `text-transform: uppercase` 26回／`border 3px rgb(242,242,242)`／
`border-radius: 2px`・`3.94px`・`20.81px`／`box-shadow: rgba(2,2,2,0.4) 0 0 6.75px`／

> 左レールも**白地に黒アイコン**だった（私は黒地にグレーアイコンで作っていた）。

### 再現の方針（実画面の観察を反映した最終版）

- **地は白**（`#fff`）。長文を読む wiki とも相性がよい。**黒は UI パーツとタグに使う**
- **左レールは白地に黒アイコン**。現在地は**黒い面に白アイコン**
- **黄色 `#fffa00` は「面」で大胆に**使う（帯・CTA・現在地）。文字色には使わない
  （白地に黄色の文字は読めない）
- 見出しは **`[ 名前 ]` の角括弧**、その下に**細いカラーバー**
- 分類は**黒背景に白文字の小さなタグ**
- 数値は**計器風**（`01 / 12` のように分母を添える）。等幅数字
- 英字ラベルは**大文字・字間広め・細字**を小さく
- 角丸は 2px。**影は `rgba(2,2,2,.4) 0 0 6.75px` 程度の弱いもの**
- ローディング画面の「黒地＋等高線」は**トップの導入部だけ**に使う

## ★ CSS の静的解析でつまずいた点（2026-09-07・鳴潮で判明）

1. **HTML から辿れる CSS が「本体」とは限らない。**
   鳴潮の `index-*.css`（75KB）は**中身が animate.css だけ**で、色が1つも無かった。
   本体は **JS バンドルの中に書かれたチャンク名**から辿る:

   ```bash
   curl -sSL "<メインの JS>" -o app.js
   node -e "const s=require('fs').readFileSync('app.js','utf8');
     console.log([...new Set([...s.matchAll(/assets\/[A-Za-z0-9_.-]+\.css/g)].map(m=>m[0]))].join('\n'))"
   ```

   これで16本のチャンクが出てきて、そこに本物の配色が全部あった。

2. **`grep -o` は1行が数万文字の圧縮 CSS で無言で失敗する**（0件を返す）。
   `grep -c color` すら 0 になったので、**必ず `node` で読むこと**:

   ```bash
   node -e "const s=require('fs').readFileSync('x.css','utf8');
     const c=new Map();
     for(const m of s.matchAll(/#[0-9a-fA-F]{6}\b|rgba?\([^)]{0,40}\)/g))
       c.set(m[0].toLowerCase(),(c.get(m[0].toLowerCase())||0)+1);
     console.log([...c].sort((a,b)=>b[1]-a[1]).slice(0,40))"
   ```

3. **色だけでなく「その色が付いた規則ごと」出すと意味が分かる。**
   `s.split('}')` して目当ての色を含む規則を表示すると、
   「この金は見出し」「この灰は罫線」までそのまま読める。**ここまでやる価値がある。**

## ★ 4回目（2026-09-08 夜）— **動きの仕組み**まで移植する

利用者の指示「そのUIの中には公式hpほど高品質ですごいものも完全再現仕組みまで」。
色と形は揃ったので、ここからは**公式の「動き」をそのまま動かす**段に入った。

### NTE — 公式のグリッチを本物として動かす

これまでは `text-shadow` の**静止した色ズレ**だけだった。
公式は見出しを**3枚重ね**、上2枚を赤とシアンにずらして
`clip-path: inset()` を **0.3s** で切り替えている。keyframes はそのまま移植した:

```css
/* 公式（.glitching）— clip-path と transform の値は一字一句そのまま */
@keyframes glitch-anim-red {
  0%{clip-path:inset(20% 0 80% 0); transform:translate(-2px,1px)}
  20%{clip-path:inset(60% 0 10% 0); transform:translate(2px,-1px)}
  … to{clip-path:inset(30% 0 20% 0); transform:translate(2px,-1px)}
}
```

**この効果には文字の複製が要る**（`clip-path` で切るのは複製した文字だから）。
公式はマークアップに `data-text` を持たせているが、こちらは `.page-head h1` を持つ
ページが **14種類**あり、1つずつ属性を書くと足し忘れが起きる。そこで

- **`BaseLayout` の末尾に小さな inline スクリプト**を置き、
  `data-ui="nte"` のときだけ見出しの文字を `data-glitch` に写す
- `data-astro-rerun` を付けて View Transitions の切替後にも走らせる
- 設定パネルで切り替えたときのために `applyUI()` からも同じことをする

**公式と変えた点は2つだけ**（どちらも理由がある）:

| 点 | 公式 | こちら | 理由 |
| --- | --- | --- | --- |
| 回数 | `infinite` | **3回で止まる**。ホバー中だけ `infinite` に戻る | wiki は長時間読むページ。常時点滅すると本文が読めない |
| 合成 | `mix-blend-mode: screen` | 明るいテーマだけ `multiply` | `screen` は明るい地で白く飛んで消えるため |

動きは `prefers-reduced-motion` と設定の「モーションを減らす」の**両方**で止まる。

### アークナイツ：エンドフィールド — ローディング画面を導入ブロックとして再現

実画面の観察にあった「黒地＋等高線（地形図）の極薄パターン／左端に細い黄色の縦バー／
大きな黄色の数字と小さな白い単位／右下に細字・大文字・字間広めの英字」を、
トップページの導入ブロック（`.ef-intro`）として組んだ。

- 等高線は `repeating-radial-gradient` を2系統ずらして重ねる（**画像は使わない**）
- 縦バーは表示時に `height: 0` から**1.1秒かけて下から伸びる**（公式の進捗表示の動き）
- **数字は実データ**（収録済みの記事数）。バーの割合も
  「記事が1本以上あるセクション ÷ 全セクション」の実数。**飾りの偽の数字は置かない**
- **公式のキャッチコピーそのものは載せない**（公式の文言なので）。
  英字ラベルはこの wiki 自身の言葉にしてある
