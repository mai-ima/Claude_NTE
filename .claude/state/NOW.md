## 記事を書くときの決まり（最重要）

- **スカウトの排出率・天井は書かない**（公式の数値が取れていない）。
  NTE でガチャ確率 1.87%（正 0.99%）を載せた前例がある。
- **出典が食い違ったら併記する**。片方を黙って採らない
  （例: 上級者イベントが PR TIMES「弓の練磨」／gamebiz「弓の試練」で不一致）。
- **取得できた出典だけを台帳に書く**。取れなかったことも記録する
  （公式サイトは JS 描画で `WebFetch` が本文を返さない。現状の一次は PR TIMES のみ）。
- 数値・詳細が未確認の記事は `status: draft` ＋ 本文に「要確認」。

## つまずきやすい所

```bash
pnpm verify        # test → 記事検査 → 型 → build → UI検査 → リンク検査
pnpm test:browser  # 実機相当（build の後。64ページ × 2端末 ＋ 320px 8ページ）
```

- **`pkill` は使わない** ／ **`test:browser` 中に `build` を走らせない**
- イベントの `end` は「◯日 06:59 まで」→ **前日**を入れる（開催中判定が1日ずれる）
- **記事0件のUIは、記事を入れるまで検証しきれない**
  （`.ef-row-desc` の省略が抜けていたのに気づけなかった）
- **公開ページに運営の過程を書かない**（`pnpm test:ui` が禁止表現で落ちる）
- **本番に出るのは `main` だけ**。PR を作るかは**利用者が決める**
